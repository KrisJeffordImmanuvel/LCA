Analysing changes in network traffic using rates of change

Threshold alarms ask how much traffic is present. This project asks how quickly it is changing. Each protocol is modelled as a function of time, and derivatives, integrals and eigen-analysis are written as matrices to catch a surge while it is still building.

02 / Rationale

A fixed threshold is always late

Every organisation depends on a network whose behaviour changes constantly, and the traffic crossing it is the main evidence a security team has. Most monitoring tools raise an alarm only when volume crosses a fixed threshold. That rule is late, because it waits until an attack is already large, and unreliable, because a threshold high enough to ignore normal busy periods will also miss a slow, deliberate escalation.

This is exactly the idea of a derivative. The first derivative finds the onset and recovery of an event and marks its peak where it crosses zero. The second derivative shows where growth begins to accelerate. The definite integral recovers the total data transferred. Arranging the traffic as a matrix lets each of these operations be applied to every channel in a single multiplication, and eigen-analysis of the covariance matrix shows which protocols surged together.

Static volume threshold

  • Fires only after the flood is already large
  • One number has to cover both quiet and busy hours
  • Misses slow, deliberate escalation
  • Says nothing about which protocols moved together

Rate-of-change detector

  • Reacts while the surge is still developing
  • The sign of f′ separates onset (+) from recovery (−)
  • A robust median/MAD baseline resists masking
  • The covariance eigenvector shows the surge's make-up
03 / Literature

Building on a multi-level SDN framework

Queiroz et al., Computer Networks (2026)

The framework turns Software-Defined Network controller telemetry into time-consistent indicators. It aligns port, flow, link and switch analyses to one shared time window, so the different levels describe the same network state.

  1. OpenFlow exposes cumulative counters. A rate is the difference between consecutive readings divided by the actual elapsed time, and negative differences from counter resets are discarded.
  2. Port rates are aggregated into switch, link and path objects with MapReduce-style group-by and joins inside a Lambda Architecture.
  3. Two baselines, one averaged over ports and one over switches, express deviation as a z-score, because averaging at a high level can hide a local deviation.
  4. Validated on a six-switch Mininet topology with Iperf3 flows. One port's z-score fell while its traffic continued, because concurrent flows raised the global mean.
doi:10.1016/j.comnet.2026.112701 · vol. 289, art. 112701
The gap this project fills

Traffic isn't Gaussian. The authors said so.

The authors describe network traffic as bursty, heavy-tailed and temporally dependent, so a three-sigma reading can't be trusted. They name median and median-absolute-deviation baselines as the robust alternative, but did not evaluate them.

This project takes up that gap in two ways:

mean, σ  →  median, MAD
level f(t)  →  rate f′(t)

The same masking effect they observed appears in the live demo when you switch the baseline to mean/σ.

05 / Concept behind the code

Calculus, written as matrices

Because the samples are equally spaced, every calculus operation becomes a sparse, banded matrix, and one multiplication applies it to every protocol channel at once.

08 / Limitations

      
What a derivative can't tell you

    

    

      
An onset detector, not a classifier
It fires when traffic starts rising and again when it stops. In the steady middle of a sustained flood, traffic is roughly constant and f′ ≈ 0. You can see this between the two spikes in the demo.

      
Malicious or legitimate?
A flood and a large legitimate file transfer are both genuine rapid increases. Pair the detector with a level-based rule and a look at source addresses before raising an incident.

      
Scale
A real capture at one-second samples has thousands of columns. A dense n × n operator would take hundreds of MB. Because S, D and A are banded, sparse storage cuts memory and time by orders of magnitude without changing any result.
